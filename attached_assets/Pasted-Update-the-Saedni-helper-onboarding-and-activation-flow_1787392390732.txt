==================================================
GOAL
==================================================

Remove the manual admin activation-code requirement from the NORMAL helper registration flow.

Currently, a helper may need an activation code from the admin. This creates delays when the admin is unavailable and can cause us to lose potential helpers.

The new normal helper journey should be:

Helper registration
→ WhatsApp OTP
→ OTP verification
→ automatic helper activation
→ automatic WhatsApp welcome/channel invitation
→ immediate access to Saedni

The admin-generated helper activation code should remain available only as an emergency/manual recovery mechanism and should no longer be part of normal onboarding.

==================================================

==================================================

Before changing code:

1. Identify the current helper registration flow.

2. Identify the current customer/requester registration and WhatsApp OTP flow.

3. Identify:
   - registration endpoint
   - OTP generation
   - WhatsApp OTP sending
   - OTP verification endpoint
   - helper activation logic
   - admin activation-code logic
   - WhatsApp Cloud API implementation
   - relevant database fields
   - relevant mobile screens

4. List the exact files that need to change.

5. Preserve all existing working functionality unless specifically changed below.

==================================================
STEP 2 — VERIFY WHATSAPP CLOUD API RULES FIRST
==================================================

Before implementing the automatic post-activation WhatsApp message, determine whether the message can legally and technically be sent as a normal/free-form WhatsApp message.

DO NOT assume that receiving an OTP opens a 24-hour messaging window.

The exact situation is:

- Saedni sends an Authentication OTP template to the helper.
- The helper receives the OTP on WhatsApp.
- The helper enters the OTP inside the Saedni app.
- The helper may never send a WhatsApp message back to Saedni.
- Saedni then wants to automatically send a welcome message containing the WhatsApp Channel invitation.

Verify the current Meta / WhatsApp Cloud API rules for this exact situation.

Specifically determine:

Does receiving an Authentication template from the business open the 24-hour customer-service window?

Do not assume that it does.

==================================================
STEP 3 — NEW HELPER REGISTRATION FLOW
==================================================

Once the permitted WhatsApp method is confirmed and ready:

1. Helper creates an account normally.

2. Helper must receive a 6-digit OTP through WhatsApp using the existing WhatsApp verification system.

3. Remove the admin activation-code requirement from normal helper onboarding.

4. The helper should NOT see instructions such as:
   - contact administration
   - request activation code
   - enter admin activation code

5. After the helper enters the correct WhatsApp OTP:

   - verify the phone number
   - activate the helper account automatically
   - mark the helper as verified/active using the existing appropriate fields
   - issue the normal authentication/session token
   - allow immediate access to the helper side of Saedni

6. No administrator action should be required.

==================================================
MESSAGE BEHAVIOR
==================================================

The welcome/channel message must:

- Be sent automatically.
- Require no admin action.
- Be sent only after successful helper verification.
- Be sent only when the helper is activated for the first time.
- NOT be sent when OTP verification fails.
- NOT be sent every time the helper logs in.
- NOT be resent every time the helper opens the app.
- NOT be sent to customer/requester accounts.

If necessary, add a database field such as:

helperWelcomeMessageSentAt

or another appropriate idempotency mechanism.

The backend must prevent duplicate welcome messages even if the verification endpoint is accidentally called multiple times.

==================================================
IMPORTANT FAILURE BEHAVIOR
==================================================

Do NOT make successful helper activation dependent on successful delivery of the welcome/channel WhatsApp message.

For example:

OTP correct
→ activate helper successfully
→ attempt welcome message

If the welcome message fails because of a temporary WhatsApp/Meta error:

- helper account must remain activated
- login must still succeed
- log the delivery failure safely
- allow an appropriate retry mechanism if needed

Do not expose WhatsApp API credentials or sensitive information in logs.

==================================================
ADMIN ACTIVATION CODE
==================================================

Do NOT completely delete the existing admin helper activation-code system from the backend.

Keep it as an emergency/manual recovery tool for administrators.

Preserve:

- Generate new activation code
- Old code invalidation
- Single-use behavior
- One-time display to admin
- Copy button
- No time expiry if that is the current implemented behavior

But remove this mechanism from the NORMAL helper registration journey.

A normal new helper should never need this code.
